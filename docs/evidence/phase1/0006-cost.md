# Migration 0006 and re-ingest costs (Phase 1A, B3)

Measured 2026-11-04, locally only, full pinned corpus (6,771 modules). No remote command was
run. Two meters, because neither sees everything:
- **local D1** (`meta.rows_read` / `meta.rows_written` from workerd's local D1): counts table
  and index rows, but statements that FTS5 runs internally against its shadow tables are
  invisible to it (`'rebuild'` reports 1 row written);
- **node:sqlite `total_changes()`**: counts every row inserted, updated or deleted, including
  FTS5 shadow-table writes, but not `CREATE INDEX` entries (not DML).

The remote estimate adds the two where they don't overlap.

## 0006 body (`migrations/0006_fts_external.sql`)
Applied to a local D1 holding 0001–0005 and the corpus, statement by statement:

| statement | rows read | rows written |
|---|---:|---:|
| 3 × `DROP TRIGGER`, `DROP TABLE modules_fts` | 58 | 0 |
| `CREATE VIRTUAL TABLE`, `'rebuild'`, rank config, 3 × `CREATE TRIGGER` | 1 | 7 (FTS writes not visible) |
| 6 × `ADD COLUMN … GENERATED … VIRTUAL` | 102 | 6 |
| `idx_modules_level` | 13,571 | 6,772 |
| `idx_modules_credits` | 13,571 | 6,772 |
| `idx_modules_sem3` (partial, 284 rows) | 7,057 | 285 |
| `idx_modules_sem4` (partial, 242 rows) | 7,015 | 243 |
| `ADD COLUMN row_hash`, `meta('schema','6')` | 21 | 3 |
| **local D1 total** | **41,396** | **14,088** |

node:sqlite over the same data: `total_changes()` = **16,008** for the body (the FTS rebuild:
docsize 6,771 rows, data/idx segments, config), plus 14,068 index entries =
**30,076** (`node scripts/remote-migration.mjs 0006_fts_external` prints this breakdown).

**Remote estimate: ≈ 30.1k rows written, ≈ 48k rows read** (41.4k + the rebuild's 6,771 content
reads). With the plan's ×1.5 headroom rule: 45k writes against the 100k/day account cap. The
plan's 16k figure predates the four filter indexes (14,068 entries), which the filtered
lexical gate needs (`docs/evidence/phase1/lexical-cost.md`).

`[1A] {"forcedReingest": …}`:

| | rows read | rows written |
|---|---:|---:|
| local D1, 0006 schema | **6,771** | **34,381** |
| FTS shadow tables | unchanged byte for byte (asserted) | 0 |
| node:sqlite `total_changes()`, 0006 schema | | 6,771 |

Rows written are the `modules` row plus every index entry the upsert's `SET` list touches
(faculty, ng, level, credits, partial sem3/sem4): about 5 per row. The old triggers read the
whole FTS table per row (FINDINGS B3: ~46M rows read for a full re-ingest).

## Ranking on a database with ingest history
The `'rebuild'` realigns FTS rowids with `modules.rowid`, so where ingest history has left
them apart, exact-bm25 ties can come back in a different order (pre-declared in
`docs/plans/phase1.md` r3, objection #25). The PR #8 reviewer measured this on a churned
database: 344 tie-only reorders, 0 score changes, and 36 queries whose top-5 code set changed.

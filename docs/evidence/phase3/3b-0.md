# 3B-0: corpus data for codes, partial codes and GE pillars

Plan: [`phase3.md`](../../plans/phase3.md) 3B-0 and §1 "Corpus facts for 3B–3H" (critic C);
pre-registration: [`phase3-prereg.md`](../../plans/phase3-prereg.md) §3 and §12.

`scripts/build-3b-data.mjs` builds every file below from the pinned corpus (release
`data-2026-2027-20260904`, moduleInfo sha256 `2d138795…80857b1`, read through
`scripts/pinned-corpus.mjs`) and the P-6 files. It makes no network call.
`node scripts/build-3b-data.mjs --check` rebuilds in memory and fails if a committed file
differs. `test/full/build-3b-data.node.test.js` runs that check in the full-corpus job.

## Files
| file | what it holds |
|---|---|
| `data/prefixes.json` | the 304 letter parts of offered codes, each with its offered-module count |
| `data/catalogue-codes.json` | the 14,359 catalogue-only codes, sorted. The Worker bundles this file (141 KB) |
| `data/catalogue-only.json` | the same codes with title and description, one row per line. Ingest loads them into D1 `catalogue_only` (migration 0008) |
| `data/ge-pillars.json` | the GE pillar table, copied unchanged from `eval/prereg/ge-pillars.json` |
| `data/collision-list.json` | the P-6 collision list (116) and its exempt pillar prefixes, copied unchanged from `eval/prereg/collision-list.json`, because the Worker and the eval workspace read `data/` and not `eval/` |
| `docs/evidence/phase3/3b-0-counts.json` | the counts below, as the script computes them |

## GE page
`eval/prereg/ge-pillars.json` names
`https://www.nus.edu.sg/registrar/academic-information-policies/undergraduate-students/general-education`
and leaves it unfetched (P-6 made no remote call). 3B-0 fetched it once, on 2026-11-07. The fetch
returned an **empty page body**: no text, so no pillar names to compare. The page is probably
rendered by script, or the fetcher was refused. **The URL and the pillar names are not
confirmed.** They stay exactly as P-6 fixed them; `data/ge-pillars.json` copies them unchanged.
A change to either goes through the lead, as the prereg file says. Each pillar prefix's modules
were checked against the pinned corpus at P-6, and the counts above show every pillar prefix
has offered modules.

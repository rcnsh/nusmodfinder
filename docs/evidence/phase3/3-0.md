# 3-0: in-Worker exact vector search, local evidence (2026-11-06)

What `docs/plans/phase3.md` §2 "3-0" asks the PR to show before any deploy: the identity proof
(A-N6, no look), the bundle size, the local startup time (B-4's pre-check) and a CPU
microbenchmark of the dense search (B-5, B2-8). Everything here ran locally. No deploy, no
remote D1 or Vectorize operation, no Workers AI call and no production URL. The live figures
(`versions upload` startup time, the smoke's mean `CPUTimeMs`, TTFB against the 3-0.0
baseline) come from the deploy.

## Identity (A-N6): no holdout look

**Result: identical result lists.** On dev, 98 of 98 queries return the same `results` (codes
and statuses) as the `eval-v0` replica, in hybrid and in dense-only mode. On the fixture, every
dense-list difference is a swap of adjacent items whose exact cosines tie within 2.2e-16, under
the plan's 1e-6 tolerance. Every swap is listed below.

### Dev set (`eval/dev`, 98 queries)

| run | ranker | dense index | compared with | identical `results` |
|---|---|---|---|---|
| `3-0` (hybrid) | this branch, working tree | the bundle `eval/runner/run.mjs` builds from `emb-bge-small-v0` | `eval/runs/v0.json` (`eval-v0`, fake Vectorize) | **98 / 98** |
| `3-0-vector` (`--mode vector`) | the same | the same | `eval/runs/v0-vector.json` | **98 / 98** |

- Commands: `npm run eval -- run --set dev --variant 3-0` and
  `npm run eval -- run --set dev --variant 3-0-vector --mode vector`. Both runs have
  `config.dense: "bundle"`. The run files carry the same query sha256 (`95710e43…`), corpus
  text sha256 (`47ab2421…`) and embedding (`emb-bge-small-v0`) as the v0 runs. Their
  `treeHash` differs from v0's by construction, so the comparison is on `results` only.
- The headline numbers equal v0's, as they must: hybrid nDCG@10 0.712, P@5 0.571; dense-only
  nDCG@10 0.672, P@5 0.537.
- Dense-only matters here: fusion is rank-based, so a hybrid page can hide a dense swap. The
  dense lists are identical too, so dev has no near-tie swaps at all.
- The comparison is a per-query equality of `status` and the `codes` array
  (the script at the end).

### Fixture (`test/dense.test.js`, 400 modules, fake embedder)

- 20 queries × 10 filter sets = 200 cells. Each runs `mode=vector&topK=50` (the whole dense list)
  and `mode=hybrid&topK=50`, once on the bundle and once on the standby
  (`DENSE_BACKEND=vectorize`, the fake Vectorize: exact cosine, id tiebreak).
- **111 dense positions differ, all swaps of adjacent items with |Δ cosine| ≤ 2.2e-16**
  (5 at exactly 0). The fake embedder counts words, so many fixture modules tie exactly; the
  bundle scores float32 rows and the fake scores doubles, so rounding orders a tie differently.
  28 hybrid pages are reordered by those swaps. No difference has |Δ| ≥ 1e-6; the test fails on
  one that does.

## Bundle size

| bundle | rows | `.bin` bytes | Worker upload (`wrangler deploy --dry-run`) |
|---|---|---|---|
| fixture (committed, `test/fixtures/vectors.bin`) | 400 | 631,976 | 692.3 KiB / gzip 76.7 KiB |
| pinned (`vec-pinned-c25f43ebfbdb-emb-bge-small-v0.bin`) | 6,771 | 10,683,976 | 10,508.9 KiB / gzip 8,638.6 KiB |
| production, dry build (2026-11-04 catalogue, fake vectors for the 169 missing texts, discarded) | 6,778 | 10,695,040 | 10,519.7 KiB / gzip 8,666.2 KiB |

- That is 16% of the 64 MiB Worker limit and about 8% of the 128 MB isolate.
- The layout is 32 B/row of filter table (not the plan's ~12 B estimate: aligned fields plus
  16 B reserved for 3B's prefix id, 3F's group id and 3H's bits), then 384 float32 per row.
- Both builds are deterministic. Rebuilding the fixture and pinned bundles reproduced
  data/vectors.json's sha256s exactly.

## The production bundle, dry run (no credentials)

- `node scripts/vectors.mjs data-version --offline`, on the cached 2026-11-04 catalogue
  (`.data/cache/2026-2027-moduleInfo.json`, sha256 `023beddd…`), gives **6,778 rows and data
  version `c1cf88518972`**, the committed `src/data-version.json`. So D1 already holds the
  rows the cutover bundle embeds, and the 3-0 cutover needs no D1 write (runbook steps 3–4 are
  no-ops; step 5 still runs).
- `node scripts/vectors.mjs build --corpus production --expect-count 6778 --offline` stops
  with **169 texts that `emb-bge-small-v0` lacks**. That is text changed or added between the
  2026-09-04 pin and the 2026-11-04 catalogue. `npm run eval:embed -- --texts … --dry-run`
  estimates ~29,047 tokens, **~53.5 neurons**, in 2 requests.
- With those texts given fake vectors, the build ran to completion: rowsKey `aeebeb1e…`
  (codes and text hashes only, so the real build gives the same one), 10,695,040 B. That
  bundle was then deleted, and the manifest and data version restored.

## Comparison script

```js
// node cmp.mjs <run A> <run B>: per-query equality of status and codes.
import { readFileSync } from 'node:fs';
const [a, b] = process.argv.slice(2).map((p) => JSON.parse(readFileSync(p, 'utf8')));
const ids = [...new Set([...Object.keys(a.results), ...Object.keys(b.results)])].sort();
const diffs = ids.filter((id) => JSON.stringify(a.results[id]) !== JSON.stringify(b.results[id]));
console.log(`${ids.length} queries, ${ids.length - diffs.length} identical, ${diffs.length} differ`, diffs);
```

# Phase 6 design gate (6-0): the shortlist mockup

The shortlist inside direction D, for Jacob to approve or change before 6C is built
(`docs/plans/phase6.md` §2; ADR 0010). One direction, `a/`: D's tokens, type and stamps set
the look, so there is no second option to compare.

Open `a/index.html` in a browser (no server, no network). It shows four states at 1280 × 800
and 390 × 664, each in light and dark. `a/index.html#solo-<state>-<desktop|phone>-<light|dark>`
shows one frame full-window; the states are `results`, `view`, `fullyear` and `print`.

| file | what |
|---|---|
| `a/page.css` | `public/styles.css` as live at `36dd3b9`, font URLs made relative |
| `a/shortlist.css` | the new pieces only, in D's tokens (no new colour) |
| `a/mockup.js` | 6B's rules over the data (status at each entry's own semester, counted / to confirm / only if invited / closed, the form order per semester against 40 units, exam overlaps, NUS's notes) and the four states |
| `a/data.js` | generated by `derive.mjs`; don't edit |
| `a/fonts/` | the page's Plex subsets and their licence |
| `derive.mjs` | the course data: the fixture's rows through `exchangeAt()` (`src/ng-reasons.js`), `explain.js` and `format.js`; EE4407 (NG-listed, no classes) from production's moduleInfo cache through `eligibility()`, as 6A's file will hold it |
| `contrast.mjs` | `scripts/contrast.mjs`'s `check()` over the mockup's tokens, and proof that `shortlist.css` adds no colour |
| `check.mjs` | Playwright: axe (WCAG 2.2 AA tags) over every state, width and theme; the 390 × 664 fold; full-page PNGs; the print page as tagged and untagged PDFs |

Re-run:

```sh
node --import ./docs/design/phase6-shortlist/json-hook.mjs docs/design/phase6-shortlist/derive.mjs   # needs the moduleInfo cache
node docs/design/phase6-shortlist/contrast.mjs
node docs/design/phase6-shortlist/check.mjs        # writes docs/evidence/phase6/mockup/
```

The committed PNGs were then reduced to a 256-colour palette (PIL, no dithering) to keep the
evidence small; contrast is measured by axe on the live render, not read from the images.

## Calls made in the mockup that the plan leaves open
- **The card's toggle** is a small outlined button with a bookmark: an outline when off; when
  pressed, a filled bookmark plus an accent edge and tint. It sits under the units at ≥ 641 px
  and, on a phone, stacked under the units in the head row's right column.
- **The shortlist button** has a filled bookmark, "Your shortlist", then each semester's picked
  units in mono. "Picked" counts every tagged pick in that semester, counted or not, as the
  plan's announcements do ("12 units picked so far").
- **The invitation question** shows only the faculty the list holds (here Business). The plan
  says "two checkboxes"; one unused one is noise. Revert if Jacob wants both always.
- **NUS's limits** (12 units to be admitted, 12 or three courses in CourseReg, G2's maximum,
  hours, 13 weeks) are said once under both semesters' totals, not repeated in each.
- **The view's close button** reads "Back to results".
- **The print preview** on a phone is the A4 page at 45 %: paper stays paper.
